# 运维与实现细节

> 本文档面向部署与二次开发，介绍运行模式、目录结构、报告口径、影子跟踪与复盘统计。快速开始请先看 [README](../README.md)。

本项目按《A股短线交易策略：14:30尾盘强势股筛选与次日冲高卖出》实现，策略规则原文见 [策略文档](../策略文档.md)。

## 目录结构

```
stock-strategy/
├── config.example.json      参数模板（复制为 config.json 后修改）
├── config.json              本地参数（已忽略，不提交）
├── positions.json           持仓与成交数据（运行时生成，已忽略）
├── scripts/tail_momentum.py 引擎（纯标准库，无第三方依赖）
├── 报告/
│   ├── 尾盘选股_YYYY-MM-DD.md    14:31 完整候选报告（含全部字段与评分明细）
│   ├── 候选_YYYY-MM-DD.json      候选结构化数据（供 14:51 复核）
│   ├── 买入清单_YYYY-MM-DD.md    14:51 最终买入清单 + 已购买清单 + 持仓处理
│   ├── 已购买清单.md             当前在持清单（随时更新，卖出后自动移出）
│   ├── 持仓监控_YYYY-MM-DD_HHMM.md 持仓监控（9:35/10:15/13:15/14:00）
│   ├── 周总结_YYYY-MM-DD.md / 月总结_YYYY-MM.md  周/月复盘（含改进建议）
│   ├── 买入清单_YYYY-MM-DD.json   当日确认/淘汰/超限的结构化记录（供复盘漏斗统计）
│   └── 最新推送.md               最近一次推送原文
├── 日志/运行记录.jsonl       每轮运行的记录（模式/结果/统计），复盘漏斗与数据质量统计的数据源
└── 日志/                    运行日志（包装脚本 tee 输出）
```

## 运行方式

```bash
E=scripts/tail_momentum.py
python3 $E --mode scan              # 14:31 全市场初筛 + 评分 + 推送
python3 $E --mode pm                # 14:51 持仓退出 + 尾盘确认 + 买入自动加入已购买清单 + 推送
python3 $E --mode exit              # 持仓监控：开盘情景判定 + 卖出信号 + 推送
python3 $E --mode exit --only-if-changed   # 非关键时点：建议无实质变化时不推送
python3 $E --mode week              # 本周复盘总结（胜率/盈亏/回撤/改进建议）+ 推送
python3 $E --mode month             # 上一个自然月复盘总结 + 推送
python3 $E --mode status            # 看已购买清单与统计
python3 $E --hold 600123 12.34 500  # 手工登记真实成交，加入已购买清单
python3 $E --close 600123 12.90     # 手工平仓：移出清单并计入统计

# 调试/复核常用
python3 $E --mode scan --dry-run                        # 只出报告不推送
python3 $E --mode pm --dry-run --no-hold                # 预览买入清单，不加入清单
python3 $E --mode exit --dry-run --force-now "2026-10-13 09:35"   # 复算指定时点
python3 $E --mode exit --test-tag "仅测试推送链路"        # 推送前加【联调测试】标记
```

`--force-now` 只改变引擎时钟（用于复算），**不会**让引擎去取未来数据：所有 K 线按「时间 ≤ 时钟」过滤，
盘后复算会在报告顶部标注「盘后复算」警示。

## 已购买清单（自动维护）

回测与前向验证按「全部买入、全部卖出」口径执行（中间的减仓/减半不执行），清单由引擎自动维护：

- **加入**：14:51 尾盘确认通过的标的，按当时现价写入 `positions.json → positions`（`source="执行"`），
  并在当条推送与 `报告/已购买清单.md` 里列出。
- **移出**：次日引擎给出「全部卖出」（含「全部卖出（最迟退出）」「全部卖出/至少减半」）且未跌停时，
  按当时价结算，记录从 `positions` 移到 `history`（保留审计），`paper.trades` 留成交用于周/月复盘。
- **不动**：「减仓/卖出」「减半（冲高回落）」等部分减仓建议只提示，清单不变、持仓数量不拆。
- 次日 9:35 / 10:15 / 13:15 / 14:00 的推送都带 `📋 已购买清单` 概览，卖出后即从清单消失。

推送颜色（企业微信 markdown 只支持三种内置颜色，`red` 不生效；飞书不认 `<font>`，推送器会自动剥掉标签只留文字）：

| 动作 | 颜色 | 显示 |
|---|---|---|
| 继续持有观察 / 待次日评估 | `info` 绿 | 🟢 |
| 减仓、减半、卖出（部分） | `warning` 橙红 | 🟠 |
| 全部卖出（含最迟退出）/ 跌停无法卖出 | `warning` 橙红 + 🔴 | 🔴 |

「全部卖出」用最接近红色的 `warning` 并加 🔴 前缀，是企微能给出的最强提醒。

## 数据源（全部实测可用）

| 用途 | 来源 | 说明 |
|---|---|---|
| 全市场涨幅榜 | 东财 `push2.eastmoney.com/api/qt/clist/get` | 单次 `pz` 上限 100，按涨幅倒序翻页到涨幅 < `pct_low` 为止；含量比 f10、行业 f100、上市日期 f26 |
| 5分钟 K 线 | 东财 `push2his.../stock/kline/get?klt=5`（主）/ 新浪 `getKLineData?scale=5`（备、交叉） | 东财为本环境唯一能同时给出成交量(手)与成交额的两源之一；`klt=10` 不存在（返回 rc=100） |
| 日 K 线 | 东财 `klt=101`（主）/ 新浪 `scale=240`（备） | 不复权，与实盘一致 |
| 实时行情 | 腾讯 `qt.gtimg.cn`（批量，含量比/涨跌停价） | 东财列表作回退 |
| 指数/涨跌家数/行业板块 | 东财 `ulist.np` + `clist fs=m:90+t:2` | 含 f124 时间戳 → 交易日守卫 |

### 10 分钟 K 线：本地合成
任何数据源都不提供 10 分钟周期，引擎把**5 分钟 K 线两两合并**成 10 分钟（结束时间标注：09:40/09:50/…/15:00，每半日 24 根，
按日内位置配对不会跨午休）。合并时要求两根 5 分钟 bar 严格相差 5 分钟，否则丢弃该桶；
只使用「结束时间 ≤ 当前时钟」的 bar，**未收盘 bar 一律不进序列**，因此不存在未来函数。

## 参数（config.json）

初筛：`pct_low/pct_high`(3/8%)、`near_limit_pct`、`min_amount_yi`(2亿)、`min/max_turnover`(2/30%)、`min_volume_ratio`(0.8)、
`max_candidates_analyze`(90)、`exclude_boards`(["bj"])、`exclude_new_days`(25)。
技术条件：`ma10m_period`(5)、`max_dev_from_ma`(3%)、`max_launch_gain`(9%)、`max_5d_gain`(15%)、
`min_upside_pct`(3%)、`min_rr`(2.0)、`min/max_stop_pct`(1.2/5.5%)。
风险与执行：`account_equity`（0 = 不给股数，只给止损价与盈亏比）、`risk_per_trade_pct`、佣金/印花税/过户费/滑点、
`force_exit_time`("1450")、`paper_track`、`max_buy_list`(5)、`push`。

评分权重 `score_weights`：日K启动形态 25、10分钟MA5启动结构 25、尾盘强度 20、成交量配合 15、市场及板块环境 10、
上方空间与风险收益比 5（合计 100）。**评分只用于排序，硬性条件失败即淘汰。**

以上涨幅区间、均线参数均为**待回测校准的初始参数**，不是市场规律；参数敏感性需回测验证（本项目未做历史回测）。

## 定时任务（工作日）

| 时间 | 任务 | 脚本 | 内容 |
|---|---|---|---|
| 14:31 | 尾盘初筛 | `tail_momentum_scan.sh` | 全市场初筛 → 日K位置 → 10分钟MA5启动 → 尾盘强度 → 评分 → 候选报告推送 |
| 14:51 | 尾盘确认 | `tail_momentum_pm.sh` | 持仓退出处理 + 按最新行情复核候选 → 最终买入清单 + 自动加入已购买清单推送 |
| 9:35 | 开盘决断 | `tail_momentum_exit.sh` | 次日开盘情景 A–E 判定 → 卖出/持有建议推送（无持仓不推送） |
| 10:00 / 10:30 / 11:00 / 11:31 | 半小时巡检 | `tail_momentum_exit.sh` | 上午每半小时判定一次持仓状态（简报格式） |
| 13:05 / 13:30 / 14:00 / 14:30 | 半小时巡检 | `tail_momentum_exit.sh` | 午后同上；14:00–14:45 自动切「尾盘窗口简报」：给出「持到 14:51」或「现在减仓」的结论 |
| 15:10 | K线快照 | `tail_momentum_ksnap.sh` | 给近几个建仓日补记 T+1/T+2/T+3 的 10 分钟K线（实际交易 + 影子池），只写文件不推送 |
| 周五 15:05 | 周复盘 | `tail_momentum_week.sh` | 本周平仓样本统计 + 规则化改进建议推送 |
| 1 日 15:05 | 月复盘 | `tail_momentum_month.sh` | 上一个自然月统计 + 改进建议推送（空月不推送） |

非交易日（行情时间戳非当日）任务直接退出、不推送。**有持仓时每个巡检时点都会推**（9:35 完整情景，其余为一句一票的简报）；
无持仓则全部静默。巡检**不带** `--only-if-changed`：设计上每个巡检时点都输出状态，而不是只在建议变化时。
`--mode pm` 内部调用 exit 时不走简报，14:51 的买入清单保持完整格式。

## 复盘总结口径（week / month）

- **统计对象**：区间内**按建议卖出平仓**的持仓（14:51 确认价建仓；按引擎卖出建议当时价结算，或 14:51 最迟退出结算），
  等额单笔、含佣金/印花税/过户费/滑点。全部买入/全部卖出按建议执行，减仓未计入，故与实盘基本一致。
- **指标**：交易笔数、胜率、平均每笔、平均盈利/平均亏损、盈亏比（均盈/均亏）、盈利因子、等额复利资金曲线、
  最大回撤、最佳/最差、最长连盈/连亏、交易成本合计。
- **选股漏斗**：交易日数、日均初筛/送分析/通过数、14:51 确认与淘汰数、未通过硬性条件主因（数字归一化后计数）、
  14:51 淘汰主因、数据校验失败日。
- **分档统计**（用于识别哪类信号更有效）：卖出原因、启动形态（A/B）、拐头时段（上午/午后）、评分档、
  启动后涨幅档、当日涨幅区间档、行业集中度。这些属性在建仓时写入 `positions.json` 的 `attrs`，平仓时并入成交记录。
- **「复盘需要改进的地方」是规则驱动的**：每条都给出触发阈值、现象数据与具体参数建议（如 `min_rr 2.0→1.5`、
  `min_stop_pct` 提高、只做 A 类形态、同板块限 1–2 只）。样本 < 8 笔只标「样本偏小」，不据此下重结论；
  样本 < 20 笔不建议调整资金规模。完整报告落 `报告/周总结_YYYY-MM-DD.md` / `报告/月总结_YYYY-MM.md`。
- **推送默认全量**（`config.json → summary_push_full`）：交易结果、漏斗明细、7 项分档、逐笔明细（上限
  `summary_push_trades`，默认 40 笔）、影子跟踪基准、**全部**改进建议。`--brief-summary` 可回摘要版。

## 影子跟踪：初筛池「随机买入」基准（扩大前向样本）

本项目**不做历史回测**，但前向验证每周只有约 4 笔，攒 20 笔要 5 周以上，分档统计无法用。影子跟踪补这个缺口：

- 14:31 初筛把**初筛池全量**（约 166–290 只，不止进入深度分析的 90 只）写进 `候选_*.json → stage1_pool`。
- 14:51 用当日现价给池里每只记一份「假设此刻买入」→ `报告/影子_YYYY-MM-DD.json`，并标注它在哪一关通过/被淘汰：
  `买入执行` / `通过超上限` / `14:51淘汰` / `14:51数据缺失` / `硬性未通过` / `未深度分析`（池里没进深度分析的尾部），
  淘汰原因用归一化文本（数字换 `#`）便于聚类。
- 次日 14:51 用当时现价结算（≈14:50 卖出），毛收益不计费用。仍是真实时点数据、无未来函数，也不是回测。
- 周/月复盘输出「影子跟踪（初筛池基准）」：总体平均次日收益与胜率、按关卡、按当日涨幅档（<3 / 3~5 / 5~8 / ≥8）、
  按评分档、按淘汰原因；并与实际执行的笔数并列对照。`diagnose()` 会自动报「某关卡可能在筛掉好票」、
  「评分与次日收益不相关」等结论（各档 ≥30 条才下判断）。
- 开关：`shadow_track`（默认 true）、`shadow_max_pool`（默认 400）。影子池不进 `positions.json`，不影响交易与持仓统计；
  14:51 任务漏跑的那一天，因缺次日快照会标记 `skip_note` 且不计入统计。

## K线快照：每笔建仓记录 T+1/T+2/T+3 的 10 分钟K线

目的：事后复盘卖出时点（当日卖点还剩多少、多持两天是赚还是亏），**实际交易与影子池同一口径都记**。

- 文件：`报告/K线快照_YYYY-MM-DD.json`，键是**建仓日 D**，`rows` 按代码存
  `{[t, o, h, l, c, v], ...}`（t 为 bar 结束时间 `HH:MM`，v 单位「手」），
  `target_days` = D 之后最早的三个交易日（T+1/T+2/T+3），`kind` 区分 `trade` / `shadow`。
- 抓取时点：`--mode ksnap`，cron 工作日 **15:10**（`tail_momentum_ksnap.sh`，no_agent，只写文件不推送）。
  之所以不在 14:51 里跑：292 只 K 线抓取要几十秒，不能拖慢买入清单推送。
- 触发条件：建仓日 D 距今 ≥ `kline_snapshot_min_gap_days`（默认 4 个自然日，此时三个交易日都已收完），
  一次 5 分钟K线请求（`lmt=400` ≈ 8 个交易日）切出三天，避免每天重复请求。
  D 距今 > `kline_snapshot_max_age_days`（默认 12 天）时 5 分钟K线已取不到，标「无法补记」。
- `complete`：三天都齐（允许停牌股缺失）或达到 `kline_snapshot_max_attempts`（默认 3）后定稿。
- 周/月复盘新增「K线快照」段落：影子池与实际交易各自的 T+1 最高（理论卖点上界）/最低/收盘、T+3 收盘，
  并给出「T+1 最高 − T+1 收盘」「T+3 收盘 − T+1 收盘」的差值；`diagnose()` 在样本 ≥30 时会提示
  「多持到 T+3 是否更优」。整个特性不做历史回测，只记录真实时点数据。


## 强制校验与合规

- 每轮先做三层数据校验：①行情自洽（OHLC/涨跌幅/新鲜度）②东财×腾讯双源交叉 ③K 线历史（排序/重复/未来日期/OHLC 越界/未来 bar）。
  关键项失败 → 不出交易名单并在报告顶部告警。
- 报告严格分区：**【事实数据】/【计算结果】/【主观判断·次日情景预案】**；数据缺失处标 `—`，不编造。
- 无候选时明确输出「今日无交易信号」，不强行推荐。
- 默认只输出分析与交易计划，**不自动下单**；推送默认关闭，开启后仅发送通知，不产生任何交易动作。
- 本策略属**待验证假设**：未完成历史回测与模拟交易前不应认定为正期望。`positions.json` 的 `paper.trades`
  会累计模拟样本，`--mode status` 可看胜率/平均盈亏/盈亏比，可作为前向验证的第一手材料。
